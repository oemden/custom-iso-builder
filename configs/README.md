# Configs

Two **distinct kinds** of files live here — do not mix them up:


| Extension | Kind of config                                                    | Configures                                                                | Files                                                         |
| --------- | ----------------------------------------------------------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------- |
| `.conf`   | **Custom ISO build configs** (bash-sourced by `create-iso.sh`)    | *which* source ISO, which preseed/autoinstall to bake in, custom ISO name | `available/`, `build/`, `templates/`                          |
| `.cfg`    | **Builder options** (also bash-sourced, but global — not per ISO) | upload toggle, overrides, logging, cleanup                                | `custom-iso-builder.cfg` (+ `custom-iso-builder-example.cfg`) |


> Rule of thumb: `.conf` = one file **per custom ISO**; `.cfg` = one file for the **tool itself**.
>
> - `.cfg` is ALSO the Debian preseed convention in `preseeds/` — that is why build configs uses  `.conf`.)

See main README → [Section 3: OS Configuration](../README.md#3-os-configuration) (`.conf`)
and [Section 2: Builder Options](../README.md#2-builder-options-custom-iso-buildercfg) (`.cfg`).

Also here: `catalog/catalog.yml` — ISO catalog cache + URL/ISO-name nomenclature matrix,
generated by `scripts/iso-catalog.sh` (plain list, committed; regenerate with `-u`; validate
configs against it with `-c`).

## `.conf` — Custom ISO build configs

Per-ISO declarations: source ISO to download, preseed/autoinstall file to bake in,
output ISO name. Flow: `templates/` (start or scaffold) → `available/` (your library) →
`build/` (**the trigger**: exactly **ONE** `.conf` here = one build; the script errors on more).
